## Navigation test page

Create a standalone experiment route so you can prototype a complex-shaped mobile bottom nav without the production `FooterNav` (which portals to `document.body`) getting in the way.

### Defaults (since no preference was given)
- **Standalone sandbox** at `/nav-test` — outside `AppLayout` (no real TopNav/FooterNav)
- **Minimal playground** — full-height canvas, mock tab state, placeholder bar ready for SVG / `clip-path` / custom shape work
- **No shape asset yet** — page first; you can drop the complex shape in next

### Why standalone
`FooterNav` mounts via portal on `document.body`. A page inside `AppLayout` will still show the real bottom nav unless we special-case the path. A route like Loading (`AppShell` only) keeps the canvas clean.

### Changes

1. **`src/routes/Paths.ts`**
   - Add `navTest: "/nav-test"`

2. **`src/pages/NavTestPage.tsx`** (new)
   - Thin page: full-height mobile-oriented layout
   - Local mock tab state (5 labels matching product: Home / Browse / Collection / Rewards / Profile)
   - Placeholder bottom bar area (easy to replace with SVG mask, custom path, elevated center, etc.)
   - Simple content area that reflects the active tab so interactions are visible
   - Safe-area padding so it feels like a real phone chrome

3. **`src/routes/AppRoutes.tsx`**
   - Register outside the `AppLayout` tree, same pattern as loading:

```tsx
<Route
  path={Paths.navTest}
  element={
    <AppShell label="Nav Test">
      <NavTestPage />
    </AppShell>
  }
/>
```

### Out of scope (for now)
- No changes to production `FooterNav.tsx` or `theme.css` bottom-nav styles
- No new tab in the real product nav
- No SoftGate / auth

### How you’ll use it
- Run dev server → open `http://localhost:5173/nav-test`
- Iterate on shape/CSS/SVG only on this page
- When the shape is right, port it into `FooterNav` + `theme.css`
